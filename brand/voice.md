# Voice

How the writing sounds across the site, the résumé, and project READMEs.

## Register

Plain, specific, and a little dry. An engineer explaining something to another
engineer who is short on time — not a personal brand, not a pitch deck.

The test: would this sentence survive being read aloud to a colleague without
either of you wincing?

## Rules

**Lead with the concrete.** "Lead a robotics software team of 9 engineers
building mission planning, task allocation and behavior orchestration for
heterogeneous drone fleets" beats "passionate about robotics". Numbers, systems,
and named technologies carry the weight.

**No superlatives about yourself.** Not "world-class", not "cutting-edge", not
"passionate". The work is the argument.

**Lowercase for machine registers.** Section keys, nav labels, spec-block keys,
and the `guilyx` handle are lowercase. Prose and headings are sentence case.
This is a deliberate two-register system: lowercase mono is the machine talking,
sentence-case display is the person.

**Contractions are fine.** "I'm not actively looking, but the inbox stays open"
is right. Formal register reads as stiff here.

**One joke per page, maximum, and it has to be true.** The hero note about the
drifting marks being a real flocking simulation qualifies: it is a joke and also
a fact. "Rockstar ninja developer" does not.

**Own the debts.** The footer credits the design lineage. README files credit
what they were built from. This costs nothing and is the difference between
influence and lift.

## Words to avoid

*leverage, synergy, passionate, rockstar, ninja, guru, disruptive,
game-changing, seamless, robust* (unless it means the control-theory sense, in
which case say which), *utilize* (say "use").

## Section titles

Prefer a term from the actual domain over a generic one, when there is an honest
match:

| Generic | Used |
| :--- | :--- |
| Experience | **Trajectory** — path planning term, and it is literally one |
| Contact | **Open Channel** — comms register |
| Projects | **Selected Builds** |
| Blog | **Field Notes** |
| Photos | **Through the Lens** |

The constraint: the term has to be genuinely from the work, not a thesaurus
result. If there is no honest domain term, use the plain word.
